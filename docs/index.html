How it works

What is Zava, really?

Microsoft’s AI Apps Global Black Belts spend their days building agentic processes for enterprise customers. An agentic process is a business workflow that used to need a human (or a brittle rule engine) and now runs on an LLM-backed agent that can read the case, make a judgment call, escalate when it’s stuck, and learn from the outcome. Expense approvals. Vendor due diligence. Contract renewals. Hiring loops. Treasury hedging. The kinds of work that today is somebody’s full-time job and tomorrow is an agent’s, with a human in the loop on the calls that matter.

A few dozen of these agentic processes running together is a fleet. A fleet needs somewhere to live. That somewhere is a control plane — a web app where you can see which agents are running, what state each case is in, where a human needs to step in, what it’s costing, and what the telemetry says. Think air traffic controller for agents.

Zava is the recipe we use internally to stand a control plane up for a specific company. It’s three Markdown skills any coding agent (Copilot CLI, VS Code, Claude Code) can read and follow. The first skill profiles the company. The second forks our substrate against that profile so the workspace looks and behaves like that specific company. The third deploys it to that company’s own Azure subscription. You stay in the loop between each step: you review the company brief, edit the brief, run the result locally, exercise the workflows, and only deploy once it actually does what you’d expect.

The skills pipeline

The three skills.

Three skills, run as a chain. Each one is a Markdown file the coding agent reads and follows. You review the output between each step before letting the next one run.

research-company
Entry skill 15–40 min

Profile the target company against the public record (Wikipedia, registry filings, annual reports, the press) and produce an org-brief.yaml. The brief names the executive team, the subsidiaries, the strategic themes, the tech stack, and the regulatory exposure. Every claim is tagged high / medium / low / inferred so you can see what to trust. You read it, correct what’s wrong, add anything internal that the public record doesn’t know about, and decide which business processes you want the workspace to model.

InputCompany name or domain
→
Outputbriefs/<slug>-org-brief.yaml
> "Use research-company to profile Contoso Bank."
Every claim tagged high/medium/low/inferred with source refs. SKILL.md →
compose-org
Fork substrate 30–60 min

Take the brief and fork the zava-control-plane substrate into a standalone repo for that customer. The skill rebrands the tokens, repacks the data fabric so the entities make sense for the industry, regenerates the personas (so the CFO in the workspace has the actual CFO’s name and remit), and scaffolds 25–35 domain stubs for the processes you picked. The output is a full repo you can run locally on your laptop.

Inputorg-brief.yaml + industry primer
→
Outputzava-control-plane-<slug>/ (standalone repo)
> "Use compose-org to fork the substrate for Contoso Bank using the banking primer."
Ten phases. Pauses for operator approval at each destructive step. SKILL.md →
zava-workspace-deploy
azd deploy ~5 min

Build the React SPA, package it with FastAPI, deploy to Azure Container Apps. OpenTelemetry feeds App Insights. The output is one container running 170+ API routes, the SSE streams the dashboard reads from, and the dashboard itself. The customer gets a URL on their own Azure subscription.

InputBranded fork + Azure subscription
→
OutputLive ACA workspace + App Insights telemetry
> "Use zava-workspace-deploy to ship this to Azure."
Single container: FastAPI serves API + React SPA + SSE + OTel. SKILL.md →

What ships

What ships in the workspace.

Every workspace, whichever customer it’s for, ships with the same substrate underneath. The brand and the personas change between customers. The plumbing doesn’t. Here’s what that plumbing is.

0+

API routes, live on Azure.

The substrate ships with everything a control plane needs: workflow lifecycle, exception handling, entity management, persona reasoning, KPIs, memory, a simulator, fleet economics, authority routing, policy enforcement, governance, and the portal itself.

FASTAPI · PYDANTIC V2 · ACA

0

Operational domains running.

A domain is one of those agentic processes — expense claims, vendor KYC, contract renewal, treasury FX, AP invoices, privacy DPIA, and so on. Each one is a full workflow with its own state machine, its own exception handlers, and the personas that decide the calls.

12 OPERATIONAL · 25 STRATEGIC STUBS

0

SSE event types streaming.

The React dashboard subscribes to a Server-Sent Events stream so the UI updates in real time without polling. The events cover workflow lifecycle, exception detection, human-in-the-loop gates, OpenTelemetry span emission, and fleet heartbeat.

Enterprise story

Where Threadlight fits.

Threadlight is the sibling recipe for building one agentic process at a time, end to end — from the customer’s process documentation, to the agent’s system prompt, to a deployed Foundry hosted agent that runs the process for real. Zava is the layer above. A lot of engagements start with one Threadlight process to prove the agent actually works against the customer’s reality, then graduate into a Zava workspace once the customer asks where the second and third processes plug in. You can also start with Zava if the customer wants to see the whole picture first and pick the hero processes after.

  Research

Research + Compose

research-company profiles the customer. compose-org forks the branded substrate. The customer sees their own org structure.

  Design

Design + Deploy Agents

threadlight-design specs 2–3 hero processes. threadlight-deploy ships Foundry hosted agents. Process-level personas handle individual cases.

  Deploy

Deploy Dashboard

zava-workspace-deploy ships the branded control plane. Executive personas orchestrate the fleet. The customer bookmarks the URL.

Or point it at a customer who’s already told you which processes they want to automate, using their own process documentation as input to the brief. Or let us imagine the processes for you — give us the company and we’ll suggest the agentic processes that fit that industry and that organisational shape, and build the workspace around them.
